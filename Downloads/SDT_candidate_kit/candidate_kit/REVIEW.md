# REVIEW.md

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How it was fixed |
|---|---|---|---|---|
| 1 | MongoClient configuration | The starter silently hard-codes fallback connection settings and doesn't make MongoDB availability explicit at startup. | Run with a missing/unreachable MongoDB service and call `/health`. | Read `MONGO_URI` and `MONGO_DB` from the environment (with local development defaults), configure a short server-selection timeout, and return 503 when ping fails. |
| 2 | `compute_late_minutes` | Naive datetimes and a same-date shift start cause incorrect late calculations for UTC inputs and overnight shifts. | Punch in just after midnight for a 22:00–06:00 shift. | Normalize instants to UTC, derive the attendance day in IST, and calculate against that day's IST shift start. Apply the strict >10-minute grace rule. |
| 3 | `compute_work_hours` | Python `round` uses ties-to-even and can disagree with the required decimal half-up rounding. | Use a duration whose hours round exactly at a half-cent boundary. | Use `Decimal` with `ROUND_HALF_UP` for two-decimal work hours. |
| 4 | `compute_overtime` | The starter doesn't roll shift end into the next day for overnight shifts and doesn't apply the 30-minute minimum. | Punch out at 06:40 for a 22:00–06:00 shift. | Derive the shift end from the attendance date and shift configuration; count whole minutes only when the result is at least 30. |
| 5 | `EmployeeIn` | The starter accepts malformed employee codes, email/date/time strings and identical shift start/end values. | Submit `emp_code="x"`, an invalid date, or equal shift times. | Add Pydantic field constraints and explicit calendar-date/shift validation. |
| 6 | `create_employee` | A read-before-insert duplicate check races under concurrent requests; `_id` can leak and `created_at` is not consistently UTC/epoch-ms. | Send two concurrent POST requests with the same `emp_code`. | Enforce a unique database index, catch `DuplicateKeyError`, store UTC datetime, and serialize `created_at` as epoch milliseconds. |
| 7 | `list_employees` | No database indexes are created and response creation timestamps were not converted to API epoch milliseconds. | Inspect the response and explain plan with many employees. | Add idempotent indexes and serialize API instants consistently. |
| 8 | `punch_in` | Unknown employees are dereferenced; timestamp zero is treated as omitted; local machine time is used; the date is not IST/overnight-aware; status and timestamp validation are incomplete; check-then-insert is race-prone. | Unknown `emp_code`, a valid explicit timestamp, invalid status, or simultaneous punch-ins. | Validate request fields, normalize/truncate timestamps, calculate the R1 attendance date, return 404 for unknown employees, and use the unique `(emp_code,date)` index for race-safe 409 conflicts. |
| 9 | `list_attendance` | It fetches the entire matching dataset into Python, sorts in memory, has no pagination validation, and returns internal `_id`-based `id` fields contrary to the contract. | Use a 100k-record collection or invalid date/page parameters. | Count with the same filters, sort/skip/limit in MongoDB, validate filters, and serialize the specified attendance fields without `_id`. |
| 10 | `punch_out` | The starter has fragile record matching and does not consistently serialize history/default fields; the update race must be handled explicitly. | Concurrent punch-outs, overnight shifts, null punch-out, and legacy records. | Use a conditional atomic update, UTC instants, R1–R5 calculations and a 409 for a losing concurrent request. |
| 11 | Missing PATCH endpoint | Manual corrections and their audit history were not implemented. | Correct a punch time twice concurrently and inspect `history`. | Validate correction rules, recompute derived fields, record only changed fields, append one audit entry, and use compare-and-swap to avoid lost history. |
| 12 | Missing analytics endpoints | Monthly, department, leaderboard and trend calculations were absent. | Request each analytics route on seeded and awkward datasets. | Add MongoDB aggregation pipelines for summaries, joins, ranking/ties, daily date-series generation and moving averages. |
| 13 | Missing explain endpoint / indexes | There was no explain endpoint or required compound indexes. | Call `/admin/explain/...` against a large dataset. | Create indexes at startup and return MongoDB `executionStats` explain output for the selected operation. |

## Reviewed and retained

- The API uses `emp_code` as the business identifier rather than MongoDB `_id`, as required by the contract.
- Calendar dates and shift times remain strings; instants are stored as BSON datetimes and exposed as epoch milliseconds.
- Missing `history`, `half_day`, `late_minutes`, and `overtime_minutes` values are handled using the documented legacy defaults.
